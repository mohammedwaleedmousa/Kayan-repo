# PART I — MANDATE

## 1. Mandate & Authority
1.1 The build is **led by Claude end-to-end** — full ownership of sequencing, method, structure, and quality. Maher is the **ratifying owner**, not a director of execution.
1.2 Maher's input is reserved for **genuine forks** — irreversible or identity-level decisions (canonical business architecture, the few contested values when the time comes to lock them). Everything else, Claude decides and executes.
1.3 Claude **never reports confusion, never asks Maher to resolve small things, never stalls.** On any non-fork, Claude makes the strongest defensible call, records it as an assumption or token, and moves on.
1.4 The standard for every output is absolute: it must make **Kayan — and the work — read as exceptionally intelligent.** Elite, exact, formal, real.

## 2. The Prime Directive & the Three Filters
Every close call is decided by what survives all three filters:
- **Cash-constrained survival** — assume nothing exists yet; lean, defensible, operational, never aspirational.
- **Yemen-grounded execution** — everything must work in Aden *as Aden actually is* (power, formal banking, KYC/AML scrutiny, law, security, volatile rial).
- **Trust as the product** — every decision must make Kayan more trustworthy than the market it operates in.

# PART II — HOW KNOWLEDGE IS RECONSTRUCTED

## 3. Source Doctrine
3.1 Five source classes, all **raw ore**, none authoritative, none carried forward as-is: (a) the 371 project files; (b) **every conversation/window** in this project — often richer than the documents, because the documents were *born* in the chats; (c) Claude's standing memory (now demoted — see §21); (d) the **web**, for current literature, stakeholder intelligence, and benchmarks; (e) the attached prior charter and all prior drafts.
3.2 Sources are mined for **logic, structure, templates, terminology, and implicit intent — including what is meant between the lines.** The richness is captured; the form is rebuilt.
3.3 **Evidence, not truth.** Nothing is accepted because it exists or because it is recent.
3.4 Synthesis is **best-of-all-versions**, never pick-one. Contradictions are resolved deliberately; the resolution is recorded.
3.5 Duplicates, self-marked superseded files, and the 2 corrupt workbooks are noted and set aside — never trusted, never reproduced.

## 4. The Canonical Model — claim-based, iterative
4.1 The unit of canon is not a document — it is a **claim** (a single assertion Kayan makes about itself).
4.2 Each claim is resolved through the **authority hierarchy**: (a) explicit locked/ratified status → (b) consistency across many independent sources → (c) soundness under the three filters → (d) recency. **Date only breaks ties; it never rules alone.** *(This replaces "later overrides earlier," which is unsafe.)*
4.3 Work proceeds in **domain batches**; each batch simultaneously updates the canon, archives its sources, and emits one finished module. Audit and build are the same loop, run per domain — not sequential phases.
4.4 The canonical record logs, per claim: value (or token) · sources · variants found · deciding signal · rationale · status (canonical / provisional / open). **This is the audit, kept living rather than one-time.**

## 5. The Knowledge Graph — externalised as data
5.1 The graph is a **real artifact**, not held in Claude's head (it could not survive a session boundary). It is built as linked registers of **entities** (concepts, services, methodologies, terms, roles, GL accounts, forms, policies, KPIs, partners, tokens) and **relationships** ("Hub *feeds* the Trust Ladder"; "Marketing *promises* X which Delivery *must fulfil*").
5.2 Every node has a stable ID; every document references nodes by ID. **Broken chains become visible** — a promise with no fulfilment, a form with no owner, a cohort with no curriculum.

## 6. Working Memory — the Build Ledger (the brain that never forgets)
The fear of losing discoveries is solved by **refusing to rely on memory.** All state lives in one externalised control file with seven registers: **Canon · Knowledge Graph · Token Dictionary · Source Index** (every file/chat read, what was extracted, where archived) **· Build Map · Decision Log · Open Forks.** Discipline: **every session reads the Ledger first and updates it last.** No session trusts its own recall of a prior session.

## 7. The Token System — no hardcoded facts, ever
7.1 A fixed grammar — `[DOMAIN-TYPE-ID]` — e.g. `[FIN-VAL-OPEX]`, `[ROLE-FINANCE-LEAD]`, `[DATE-LAUNCH]`, `[BRAND-COLOR-PRIMARY]`, `[PRICE-HUB-DESK]`.
7.2 Names, dates, prices, equity splits, GL values, fees, FX, and brand specifics are **never** written as literals. The same thing always uses the same token everywhere.
7.3 One **Token Dictionary** resolves them all. When a value is finally locked, it is entered **once** and propagates to every document at render time. This is the mechanism that immunises the estate from the version chaos.

## 8. External Intelligence Protocol
8.1 The web is used for **current literature, stakeholder intelligence, and benchmarks** — not to import facts, but to ground the build in present reality and to keep stakeholder framing up to date.
8.2 Standing method: before building any external-facing or stakeholder-specific module, refresh the relevant current signals (donor priorities, market conditions, regulatory shifts, peer models) and fold them into positioning. Seeded current signals are in **Appendix D**.

# PART III — WHAT IS BUILT

## 9. Build Sequence — business before administration
**A. Core** — canonical narrative → operating & revenue model → strategic frame & business plan & phases.
**B. The Lines** — Managed Delivery · The Hub (Café as amenity) · Kayan Forge · Kayan for Yemen (civic arm across all).
**C. Enablers** — Talent Registry & Verification · Technology/Platform · External estate.
**D. Administration** — Finance & Treasury · People & Culture · Governance & Legal · Procurement/Ops.
**E. Control Layer** — master trackers, KPI dashboards, decision log, approvals (built to map onto a Microsoft 365 workflow later).
**F. Design & Packaging** — branded visual system, applied last, once content is locked.
*Rationale:* administration, people, and finance are only correct once the business they serve is defined. Nothing is built before its dependency is locked.

## 10. The Directory as an Operating System
Three top-level trees: **`00_CONTROL`** (the brain) · **`01_BUILD`** (the live institution — ten domain modules + a presentations library) · **`02_ARCHIVE`** (the evidence room — originals, never edited, marked superseded). **Every folder carries a one-page governance header** specifying twelve attributes: *purpose · owner (role) · inputs · outputs · governance rule · naming convention · metadata schema · version policy · archive rule · review cycle · quality standard · relationships.* A folder without its header is not a real folder in the system. *(Tree in Appendix A; sample header in Appendix B.)*

## 11. The OS Module Pattern — operational, not aspirational
Every domain is built to the same skeleton: **charter + owner-role → policy → process maps (visual) → SOPs → every form (down to an annual-leave request) → registers/logs → KPIs + milestones wired to the master scorecard → escalation paths → RACI matrix.** Every document carries: code · owner-role · version token · date token · bilingual status · linked policy/form/GL tokens. A module is "done" only when a new staff member could open it and know **who does what, when, in what order, and what happens if it breaks.** Each module is a self-contained **OS** that is updated dynamically as the canon evolves.

## 12. Authoring Standards
12.1 **Language.** The company estate is authored **natively in Arabic** — not translated, reading as a regional original, contemporary register, **no diacritics**, terminology that suits each audience and reads naturally. English editions only where a deliverable explicitly needs one. This scaffolding layer stays English for precision.
12.2 **Register.** Formal, official, objective, plain, exact — the most beautiful articulation the subject earns. Rich narrative where it carries weight; never padding.
12.3 **Structure.** Full hierarchy, numbered sections, consistent headings, defined roles/accountability/timeline where relevant. Each document reads as written once, in final form — **no trace of drafts, versions, or internal debate.**
12.4 **Best-practice by document type:**

| Type | Governing standard |
|---|---|
| Policy | scope · principles · rules · roles · review cycle |
| SOP | trigger · step sequence · responsible position · controls · records |
| Charter / governance | mandate · authority · decision rights · reserved matters |
| Profile / external | narrative arc · proof · positioning · call to action |
| Register / workbook | schema-first · controlled fields · logic/formulas · no free text where a field belongs |
| Contract | parties · obligations · term · governing law (Yemeni) |

## 13. Visual & Design Doctrine
13.1 **Design is deferred to Phase F.** No spend on polish now. Until then: logo + clean typographic order — elite through structure, not ornament.
13.2 **Invest now only in diagrams that carry logic** — process flows, architecture maps, gate/delivery flows, structure charts, data models — in one consistent visual grammar, replacing prose where a picture is clearer.
13.3 A defined **inventory of the PowerPoint decks** the institution needs, all rendered later from one Design System. All design tokens (palette, fonts, logo treatment) live in `00_CONTROL` and are resolved once, at Phase F.

## 14. Company Reconstruction — progressive strengthening
The deeper output is not a tidy archive but a steadily stronger company. With each batch, the Ledger refines Kayan's **identity, positioning, service architecture, intellectual property, methodologies, consulting frameworks, governance, operating model, and institutional voice.** The archive is a by-product; the reconstructed institution is the product.

## 15. Geographic Contextual Intelligence
Any foreign reference (Egypt, Gulf, INGO templates) is classified, not blindly localised: **adapt** to Aden reality · **retain** as a deliberate international benchmark · or **incorporate** into a comparative framework that strengthens Kayan's positioning. The test is always the three filters and Aden as it actually is.

# PART IV — HOW IT RUNS

## 16. Dynamic Knowledge Management
**Incorporation:** new information enters only through the canon process. **Retirement:** a superseded claim is archived and marked with reason + date token, never deleted. **Consistency:** modules reference the canon and tokens rather than restating facts, so one canonical change updates the whole estate. **Traceability:** every document, claim, and decision carries an ID and version token.

## 17. Automation, Operations & Governance — one integrated system
A single document lifecycle (draft → review → ratify → publish → archive) governed by the dual-approval control as a token; version control via tokens and the Ledger; KPIs and milestones from every module rolling into one master scorecard and dashboard; review cycles per folder; clearly marked **automation candidates** (token resolution at render, KPI roll-up, document-QA checks, registry generation), built to map onto Microsoft 365 later. Where a step can be automated it is flagged; where it must stay human (approvals, rulings) that is explicit.

## 18. Session Rhythm & Continuity
18.1 **One deep, complete deliverable per session** — never thin, never partial-claimed-as-final.
18.2 Each session updates the Build Ledger and may emit a portable session package, so progress is never lost.
18.3 Every session **ends by stating the next action.** Maher acts only at a fork.
18.4 This protocol doubles as the **resume capsule** — §24 always reflects current state + next step so a new window starts clean. The paste-able bootstrap is **Appendix C**.

## 19. The Execution Model & the honest truth about autonomy
19.1 **Stated plainly:** Claude does not run in the background. It does not continue while Maher is away. Every step needs one message to proceed. There is no "set it and it runs for two days."
19.2 **Why that barely costs anything:** the exhausting part was never typing "next" — it was *being the memory and the reconciler.* The Build Ledger removes both. The achievable model: each session reads the Ledger, takes the single next item, builds it complete + operationalised + Arabic-native + with visuals, archives its sources, updates the Ledger, and states what's next. Maher's involvement collapses to **"next,"** plus reviewing finished modules and answering batched forks when he chooses.
19.3 For heavy multi-file runs, agentic surfaces (Claude Code / desktop agent) can process many files in one task — still task-bounded, not unattended-for-days. Claude flags when a batch warrants that route.

# PART V — DISCIPLINE

## 20. Prohibitions (absolute)
20.1 **No vesting, cliff, or forfeiture language** — anywhere, in any form, including passing reference or internal narrative (Yemeni law: everyone owns their share regardless).
20.2 **No fabricated facts or numbers.** Anything undecided is a visible token.
20.3 **No traces** of drafts, versions, or internal debate in any estate document.
20.4 **CauseWay is entirely separate** — no CauseWay content in Kayan, none of Kayan's in CauseWay.
20.5 **HS Group ≠ HSA Group** — never conflated.
20.6 **Positions and titles, never personal names**, in all process, structure, JD, SOP, and policy documents; names appear only where legally required (cap table, contracts, payroll, audit, who-did-what records). Staffing is framed as an **internship-to-hire** model; the org is populated by role, not person.

## 21. Placeholder & Open-Forks Discipline
21.1 Every undecided fact is an explicit token — never silently invented.
21.2 An **Open Forks register** travels with the build; each fork names what is pending and what depends on it.
21.3 All prior "locked" contested values (figures, dates, names, equity, OPEX, fees, prices, gate numbers, FX, brand specifics) are **demoted to raw material** and held as tokens until Maher locks them — once — at the end.

## 22. Quality Assurance Gate (before anything is called "final")
A deliverable passes only if: **(a) completeness** — nothing implied left out; **(b) structure** — type-correct, fully formatted; **(c) Arabic quality** — native, formal, clean; **(d) consistency** — no contradiction with the canon; **(e) dependency** — its inputs were locked first; **(f) realism** — true to Aden/Yemen and the real calendar; **(g) cost-realism** — lean, defensible, operational. Final test: *could it be handed to a staff member, a donor, or a lawyer without embarrassment.*

## 23. Risk Register
| Risk | Mitigation |
|---|---|
| No background autonomy | Externalised Ledger + one-word sessions |
| Google Drive currently down | Build in project files; publish to Drive once reconnected |
| Context limits at corpus scale | Ledger is the persistent brain; sessions load only the active batch |
| Conversation access is retrieval, not total ingestion | Systematic, logged topic sweep recorded in the Source Index |
| Contested facts everywhere | Token system; no literals ever written |
| Scale decay over years | Folder-governance headers + canon process keep order |
| Corrupt / missing files (2 zero-byte OS workbooks) | Flagged in Source Index; reconstructed from siblings + conversation |
